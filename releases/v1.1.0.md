# JuHex Binary CLI v1.1.0

## Native Packages

Download the five native archives and `SHA256SUMS.txt` from the GitHub Release for tag `v1.1.0`.

## Changes Since v1.0.24

- Compact: fixed failed and session-memory progress states, no premature 100%, idle-aware compaction, per-model auto-compact windows, and the `/autocompact` command.
- Concurrency: bounded streaming tool execution, subagent concurrency and nesting limits, per-agent request limits, endpoint pool admission queues, per-provider quota isolation, DAG scheduling with retries, and faster wakeups after capacity is released.
- Workflows: `Workflow` supports sequential, parallel, and dependency-aware `dag` execution, per-step retries and journal receipts, and resume of interrupted runs with `resumeRunId`. `/workflows` shows active, persisted, and recent runs.
- Knowledge and prompts: binary knowledge is gated by recognized binary signals, uses word-boundary matching, resets per user turn and on `/clear`, and no longer scans the whole corpus on tag misses. The expert prompt now uses a compact core plus task-triggered technique references.
- Commands: `/verify` and `/simplify` discover the current repository's manifests, scripts, and CI instead of assuming the JuHex source layout. `/agent-view`, `/focus`, `/tui`, and `/workflows` are registered.
- Optional tools: Code Mode, Guardian high-risk command review, and the Workflow tool remain opt-in.
- Providers: refreshed OpenAI/Codex GPT-6.2 defaults, Kimi K2.5, GLM-4.7, and current first-party model defaults.
- Reliability: streaming fallback now cancels the discarded executor, tool receipts avoid re-running a completed side-effecting call after fallback, and workflow journals have bounded prompts, artifact retention, and path traversal guards.
- Backend and VS Code extension fixes are included in the development repository; backend archives remain separate from the public CLI release.
